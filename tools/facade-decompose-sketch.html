Decomposing a complex footprint into component blocks

The generation system already emits a building as sections (rects + shape archetypes — round, ell, courtyard…). We don't generate the whole blob; we quantize oversized sections into ≤12-tile patches (the dashed red grid = PixelLab's 400px / 12.5-tile max), then classify each patch by which sides are EXPOSED, pull the matching oriented block, and flow one roof over the union.

interior → ROOF only (no walls — never seen) south edge → FACADE block E/W edge → EDGE block (rotated) corner → CORNER block (rotated) curved → ROUND / portico block north back → not seen outside (interior)

The algorithm

  1. Sections in — take the footprint's sections from the generation system (already rects + archetypes).
  2. Quantize — any section bigger than ~12 tiles is tiled into ≤12-tile patches (dashed grid).
  3. Classify each patch by exposed sides: 0 exposed → roof-only; south exposed → facade; E/W → edge; south+side → corner; curved boundary → round/portico.
  4. Orient — pull the block from the library in the needed direction (see rotations below).
  5. Roof — one surface (procedural) or roof-blocks flow over the whole union; foundation only on the south-exposed base; stories stack as slices.

Rotations — you're right, but cheaper than 8× everything

We need a directional set (the stone_160 idea): 4 cardinal EDGES + 4 CORNERS. But it's not 8× every asset — • the big interior is roof-only (no walls), so most of a huge building is just roof; • the south facade is generated once; • west = mirror(east) and the north back is rarely seen → derived, not generated; • round pieces are near radially-symmetric. So per material we generate ~south-facade + E-edge + SE-corner + round and derive the rest — a handful, not 8×N.
