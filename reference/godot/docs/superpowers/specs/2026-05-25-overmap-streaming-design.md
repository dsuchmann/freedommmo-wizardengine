# Overmap + Streaming Terrain Design

> Established 2026-05-25. Integrates the overmap navigation system with the deterministic WorldCompiler terrain pipeline.

## Core Principle: Deterministic World From Seed

The entire world is defined by a single integer seed. The same seed + coordinates produce the exact same terrain on every client, every time. No server-side terrain storage needed. No pre-rendering needed. The seed IS the world.

- World seed: stored in `ServerConfig` (default: 42)
- World capacity: 6,400 × 6,400 chunks = ~41 million chunks
- Each chunk: 64×64 tiles at 32px = 2,048×2,048 pixels
- Total world: ~13 million pixels per side
- Walking time to cross: ~33 hours continuous
- Only ~25 chunks loaded at any time

## 1. Overmap

A 6,400×6,400 pixel Image where each pixel represents one chunk. Generated by evaluating the elevation + climate noise functions at each chunk's center world coordinate. Pixel color encodes biome type.

### Generation
- Sample elevation noise at `(chunk_x * 64 + 32, chunk_y * 64 + 32)` for each pixel
- Sample climate noise at the same position for temperature/precipitation
- Classify biome from elevation + climate (same thresholds as BiomeLayer)
- Set pixel color from BiomeLayer.biome_color()
- Total: 41M noise evaluations. Target: ~30 seconds.
- Cache result as PNG at `user://overmap_{seed}.png` for instant reload

### Display
- TextureRect on a CanvasLayer overlay
- Press `M` to toggle open/close
- Red marker shows current player position (updated from player world pos / chunk pixel size)
- Click a pixel to teleport (see Section 3)

### Biome Colors (same as BiomeLayer)
| Biome | Color |
|-------|-------|
| Ocean | Dark blue (0.1, 0.2, 0.5) |
| Beach | Tan (0.9, 0.85, 0.6) |
| Grassland | Green (0.4, 0.75, 0.3) |
| Forest | Dark green (0.15, 0.5, 0.15) |
| Desert | Sandy (0.85, 0.75, 0.45) |
| Mountains | Gray (0.55, 0.55, 0.55) |
| Tundra | White-blue (0.7, 0.75, 0.8) |
| Swamp | Murky green (0.3, 0.4, 0.25) |

## 2. Chunk Streaming

### Loaded Grid
- 5×5 grid of chunks around the player (25 chunks loaded)
- Each chunk rendered via TileMapTerrainRenderer onto shared TileMapLayer nodes
- Total visible area: 320×320 tiles = 10,240×10,240 pixels

### Movement Detection
- Every frame, compute which chunk the player is in
- When player crosses 60% toward a grid edge, trigger loading of the next row/column in that direction
- Loading happens one chunk per frame via `await get_tree().process_frame`

### Chunk Lifecycle
```
Player approaches edge
  → ChunkStreamer._check_grid_expansion()
  → For each new chunk position:
      → ChunkCache.try_load(cx, cy)
        → HIT: deserialize ChunkData from binary, skip compilation
        → MISS: compile via two-phase pipeline (see below)
      → TileMapTerrainRenderer.register_chunk(chunk)
      → TileMapTerrainRenderer.render_chunk(chunk)
  → Unload chunks > 3 rows behind player:
      → TileMapTerrainRenderer.clear_chunk(cx, cy)
      → Remove from renderer._chunks dictionary
```

### Incremental Two-Phase Compilation
When streaming (not bulk-compiling), new chunks compile using neighbor context:

1. **Phase 1**: ElevationLayer + OceanMaskLayer compile on the new chunk (uses world_seed noise — inherently seamless)
2. **Edge propagation**: Copy ocean_distance values from already-compiled neighbor chunks' edges into the new chunk's border cells, then run local BFS inward. This replaces the global BFS with O(chunk_edge) work.
3. **Phase 2**: ClimateLayer + BiomeLayer + VegetationLayer + CoastalLayer compile using the corrected ocean_distance data

This produces seamless terrain without needing all chunks compiled upfront.

### Performance Budget
- Chunk compilation: ~50ms (GDScript)
- Chunk rendering: ~20ms (TileMapLayer.set_cell)
- At 1 chunk per frame (60fps): ~70ms per chunk = fine, no frame drops
- Streaming 5 new chunks (one row): ~5 frames = 83ms total
- Player walking speed: 3.4 tiles/sec = crosses a 64-tile chunk every ~19 seconds
- 19 seconds between row loads. Plenty of buffer.

## 3. Click-to-Teleport

When overmap is open and player clicks:

1. Map pixel (px, py) → chunk coordinates (px - 3200, py - 3200)
2. Clear all loaded TileMapLayer cells
3. Show "Traveling..." label
4. Compile 5×5 grid around target chunk (~25 chunks, ~1.25 seconds)
5. Teleport player to center of target chunk
6. Close overmap, resume gameplay

Player position marker on overmap: `marker_pos = player_world_pos / (ChunkData.SIZE * TILE_SIZE)`

## 4. Binary Chunk Cache

### Format
```
u32 magic (0x434B4E4B = "CHNK")
u16 version (1)
i32 chunk_x
i32 chunk_y
i32 world_seed
u16 size (64)
[PackedFloat32Array elevation — 4096 floats]
[PackedByteArray ocean_mask — 4096 bytes]
[PackedFloat32Array ocean_distance — 4096 floats]
[PackedFloat32Array temperature — 4096 floats]
[PackedFloat32Array precipitation — 4096 floats]
[PackedByteArray biome_id — 4096 bytes]
[PackedByteArray vegetation_density — 4096 bytes]
[PackedByteArray vegetation_species — 4096 bytes]
[PackedFloat32Array slope — 4096 floats]
```

### Storage
- Location: `user://chunks/{cx}_{cy}.bin`
- Size per chunk: ~70KB (mostly float arrays)
- 1000 cached chunks = ~70MB (reasonable)
- Seed validation: if cached chunk's world_seed doesn't match current seed, discard and recompile

### Cache Policy
- Save after first compilation
- Load on revisit (skip compilation)
- Invalidate when world_seed changes
- No size limit — disk is cheap, player exploration is valuable

## 5. File Architecture

| Component | File | Lines (est.) | Responsibility |
|-----------|------|-------------|----------------|
| CleanWorld.gd | Existing (~180 lines) | ~250 | Scene controller: player, camera, bokeh, overmap toggle, teleport |
| OvermapGenerator | `scripts/core/overmap_generator.gd` (new) | ~120 | Generate 6400×6400 Image from noise. Cache as PNG. |
| ChunkStreamer | `scripts/core/chunk_streamer.gd` (new) | ~200 | Manage 5×5 grid. Detect movement. Compile/load/unload chunks. |
| ChunkCache | `scripts/core/chunk_cache.gd` (new) | ~150 | Binary serialize/deserialize ChunkData. File I/O. |
| WorldCompiler | Existing | Unchanged | Compile chunks from layers |
| TileMapTerrainRenderer | Existing | Unchanged | Render chunks to TileMapLayers |

**Data flow:**
```
Player moves → ChunkStreamer detects edge approach
  → ChunkCache.has(cx, cy)?
    → YES: ChunkCache.load() → skip compilation
    → NO: WorldCompiler two-phase compile → ChunkCache.save()
  → TileMapTerrainRenderer.render_chunk()
  → Unload distant chunks

Player presses M → OvermapGenerator.get_or_create() → display overlay
Player clicks overmap → CleanWorld._teleport_to(chunk_x, chunk_y)
  → Clear grid → compile 5×5 → render → teleport
```

## 6. What This Does NOT Include

- Rivers (need cross-chunk flow simulation — separate effort)
- Settlements, buildings, NPCs (Layers 2-7 — future work)
- Multiplayer synchronization (same seed = same world, but player positions need networking)
- Sound or music (future layer)

This spec covers ONLY: overmap generation, chunk streaming, click-to-teleport, and binary caching — all operating on the existing Layer -2 terrain pipeline.
