Hybrid Cliff + Wall Face: How It Actually Works

Breaking down the technical approach for the concerns raised

The Cliff System Today

Our terrain already has elevation levels (0-9). When tile A is at elevation 3
and tile B (south of A) is at elevation 2, the cliff renderer draws:
┌──────────────┐ ← top of elevated tile (floor)
│ Floor tile │ ← terrain Wang tile at elevation 3
├──────────────┤ ← cliff edge
│▓▓ CLIFF FACE ▓▓│ ← south-facing vertical surface (cliff overlay)
│▓▓▓▓▓▓▓▓▓▓▓▓▓▓│ ← height = elevation difference × cliff_height
└──────────────┘ ← ground level
This is EXACTLY what a building wall is.
Building floor = elevated tile. Wall face = cliff face. Already rendered
with correct lighting, z-order, corners, side edges.

Concern 1: Stacking Height

Current cliff face tiles are fixed height per elevation step.
For buildings, we control the height per step.
Option: Building elevation uses a TALLER cliff face tile.
- Terrain cliff step = ~16px face height (subtle hills)
- Building cliff step = ~48-64px face height (one story wall)
- 2-story building = elevation +2 = two stacked face tiles
- Castle = elevation +5 = five stacked face tiles
The cliff system already supports variable-height faces.
We just need a "building wall" face tile instead of a "rock cliff" face tile.

Concern 2: Windows on Cliff Faces

The cliff face is a sprite drawn at a known position.
We can composite window sprites ON TOP of it.
Layer 1: Cliff face tile (plain stone/brick wall)
Layer 2: Window overlay sprite (with alpha channel)
Layer 3: Interior glow pass (light from inside at night)
Window sprites are generated with:
- Transparent background (alpha channel)
- Correct 3/4 perspective matching the cliff face angle
- The wall face texture BEHIND the window is visible through glass
- At night: warm glow emanates from window (additive blend)
Windows are OVERLAY objects, not modifications to the wall tile. Same window sprite works on any wall material.

Concern 3: Camera Angle Matching

The cliff face has a known angle (determined by tile_view).
Wall face sprites match this angle by using the same PixelLab settings.
Terrain cliffs use: "high top-down" view → ~15% depth
Wall face tiles use: same "high top-down" → same perspective
Window overlays use: same view settings → angles match
Everything generated with the same PixelLab view setting automatically shares the same camera angle.

Concern 4: Light + Alpha Through Windows

Windows need to show interior through glass AND emit light at night.
Daytime:
Wall face (opaque) + window overlay (semi-transparent glass)
Through the glass alpha: interior floor/furniture visible
Nighttime:
Same layers + warm light rectangle (additive blend)
Creates the classic "glowing windows at night" RPG effect
This is a compositing problem, not a generation problem. The renderer layers: wall → window (alpha) → light (additive).

Implementation Steps

Step 1: Building tiles get elevation +1 in chunk compiler
→ cliff system auto-renders south face, side edges, corners
Step 2: Generate "building wall" cliff face tile (brick texture)
→ replaces the rock cliff face at building positions
Step 3: Generate window overlay sprites (alpha, matching angle)
→ composited on south face at window positions
Step 4: Generate door overlay sprites (alpha)
→ composited on south face at door positions
Step 5: Night lighting pass
→ warm glow rectangles at window positions (additive blend)
Step 6: Roof (separate system — covers the elevated platform)
→ alpha-fades when player enters building
