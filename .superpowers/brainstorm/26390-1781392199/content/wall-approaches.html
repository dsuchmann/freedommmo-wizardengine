Building Wall Rendering: Which Approach?

How should walls look in our 3/4 top-down view? Each approach handles south walls, side walls, corners, and interiors differently.

A

Cliff-Face Model (recommended)

Walls ARE cliff faces. The building floor sits at elevation +1. The south edge drops down showing a wall face (like terrain cliffs). East/west edges show thin cliff sides. North edge shows the wall cap from above. Corners get cliff corner tiles.

How it works:
- Floor tiles at elevation 1 (chunk pipeline, already done)
- South edge: cliff face overlay = wall face sprite (windows/doors)
- East/west: thin cliff side overlay (1-2px dark edge)
- North: wall cap from above (existing Wang tileset)
- Corners: cliff corner tiles (already exist for terrain)
Key insight: We already render cliff faces. Wall = mini cliff.

Pros

  • Reuses existing cliff rendering pipeline
  • Correct lighting (same as terrain cliffs)
  • Correct z-order (cliff system handles this)
  • Corners already solved by cliff tile connectivity
  • Side walls are just cliff edges (thin, natural)

Cons

  • Wall faces limited to cliff face height (~2 tiles)
  • Multi-story needs stacked elevation levels
  • Window/door overlays on cliff faces = new work
B

Sprite Wall Segments

Each wall direction is a separate sprite type. South = tall face sprite (256px). East/West = dedicated side-view sprites generated at correct angle. North = thin cap sprite. Corners = dedicated corner sprites. All drawn as overlay objects after terrain.

How it works:
- South: wall face sprite (what we have now, just tiled correctly)
- East/West: new side-angle wall sprite (PixelLab, slight perspective)
- North: thin cap or invisible (facing away)
- Corners: dedicated corner piece sprites
- Each type generated separately via PixelLab
Needs: 4+ sprite types per wall material, composited manually

Pros

  • Full control over each wall direction's look
  • Can make walls any height (not limited by cliff system)
  • Each direction is a custom sprite — maximum visual quality

Cons

  • 4+ sprite types per material = lots of PixelLab generation
  • Manual z-ordering (current broken approach)
  • Lighting mismatch (sprites bypass chunk pipeline)
  • Corner seams hard to get right without Wang system
  • Side wall perspective hard to get right in top-down
C

Hybrid: Cliff + South Face Overlay

Use the cliff system for elevation, z-order, lighting, side edges, and corners. THEN overlay the south-facing wall face sprite ON TOP of the cliff face for visual richness (brick texture, windows, doors). Best of both worlds.

How it works:
- Floor at elevation +1 in chunk pipeline (cliff system kicks in)
- Cliff renders: south face, side edges, corners — correct lighting
- South face: wall sprite overlaid on cliff face (brick + windows)
- East/West: cliff edge handles it (thin dark line, correct)
- Corners: cliff corner tiles (already seamless)
Cliff does structure. Sprite does beauty.

Pros

  • Correct z-order from cliff system
  • Correct lighting from cliff system
  • Corners and side edges solved by cliffs
  • Rich south face from dedicated sprite (windows/doors)
  • Existing wall face sprites reused (256px brick + variants)

Cons

  • Two systems (cliff + overlay) = more complexity
  • South face sprite must align with cliff face height
  • Need to figure out how to inject elevation into chunk compiler for buildings

Current State

We have floor Wang tiles rendering in the chunk pipeline (correct lighting/z-order). South wall sprites (256px stone brick with window/door variants) tile well but are drawn as a separate canvas pass — causing wrong z-order, no lighting, stretched proportions. Side walls and corners don't work.

The cliff rendering system already solves elevation differences with south-facing faces, side edges, and corners. Buildings are essentially platforms at elevation +1.
