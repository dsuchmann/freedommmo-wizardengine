1| # Dynamic Lighting & Shading System
2| 
3| > Established 2026-05-26. Authoritative spec for Layers -1 and 7: terrain shading and dynamic world lighting.
4| 
5| ## Problem
6| 
7| The terrain is flat-looking — elevation data exists but isn't visually communicated. There's no day/night cycle, no shadow direction, no atmosphere. The world feels static.
8| 
9| ## Solution
10| 
11| A unified lighting system with a moving sun/moon, terrain normal maps for dynamic hillshading, global ambient tint for atmosphere, and infrastructure for building occlusion and point lights.
12| 
13| ## Architecture
14| 
15| ```
16| DayNightCycle (time source)
17|   → drives DirectionalLight2D (sun/moon angle, color, intensity, height)
18|   → drives CanvasModulate (global ambient tint)
19|   → drives HUD (time display in dev mode)
20| 
21| NativeChunkCompiler (C++)
22|   → generates terrain Image (existing)
23|   → generates normal map Image (new — from elevation data)
24|   → bakes static ambient occlusion into terrain image (new)
25| 
26| ChunkStreamer
27|   → assigns terrain texture + normal map to each chunk Sprite2D
28| 
29| Future:
30|   Building tiles → LightOccluder2D (walls block light, windows pass)
31|   Object system → PointLight2D (torches, campfires, lanterns)
32| ```
33| 
34| ## Component 1: Sun/Moon Directional Light
35| 
36| A single `DirectionalLight2D` node represents the dominant sky light source.
37| 
38| ### Sun Arc (Dawn to Dusk)
39| 
40| The sun moves west to east across the sky:
41| 
42| | Game Hour | Period | Angle (degrees) | Height | Color | Energy |
43| |-----------|--------|-----------------|--------|-------|--------|
44| | 5:00 | Dawn start | 270 (west) | 0.2 | Warm orange (1.0, 0.6, 0.3) | 0.3 |
45| | 7:00 | Morning | 240 | 0.5 | Soft yellow (1.0, 0.9, 0.7) | 0.8 |
46| | 12:00 | Noon | 180 (overhead-south) | 1.0 | White (1.0, 1.0, 0.95) | 1.0 |
47| | 17:00 | Golden hour | 120 | 0.5 | Deep amber (1.0, 0.7, 0.3) | 0.8 |
48| | 18:00 | Dusk start | 100 | 0.3 | Red-orange (0.9, 0.4, 0.2) | 0.4 |
49| | 20:00 | Dusk end | 90 (east) | 0.1 | Fading (0.4, 0.2, 0.15) | 0.1 |
50| 
51| ### Moon Arc (Night)
52| 
53| | Game Hour | Angle | Height | Color | Energy |
54| |-----------|-------|--------|-------|--------|
55| | 20:00 | 270 (west) | 0.1 | Cool blue (0.2, 0.25, 0.45) | 0.15 |
56| | 0:00 | 180 (overhead) | 0.4 | Silver-blue (0.25, 0.3, 0.5) | 0.2 |
57| | 5:00 | 90 (east) | 0.1 | Fading blue (0.15, 0.2, 0.35) | 0.1 |
58| 
59| All values smoothly interpolated using the existing `DayNightCycle` hour as the driver. No hard transitions.
60| 
61| ### Height Property
62| 
63| The `height` property on DirectionalLight2D controls how "steep" the light hits the surface:
64| - Low height (0.1-0.3) = long dramatic shadows at dawn/dusk
65| - High height (0.8-1.0) = short/no shadows at noon
66| - This interacts with the terrain normal maps to create realistic hillshading
67| 
68| ## Component 2: Terrain Normal Maps
69| 
70| For each chunk, the C++ `build_chunk_image` generates a second Image — the normal map.
71| 
72| ### Normal Map Generation (in NativeChunkCompiler)
73| 
74| For each tile at position (x, y):
75| 1. Sample elevation at (x-1, y), (x+1, y), (x, y-1), (x, y+1) — we already compute this for the slope array
76| 2. Compute surface normal: `nx = (left - right) * scale`, `ny = (up - down) * scale`, `nz = 1.0`
77| 3. Normalize the vector
78| 4. Encode to RGB: `R = nx * 0.5 + 0.5`, `G = ny * 0.5 + 0.5`, `B = nz * 0.5 + 0.5`
79| 5. Scale = tuning parameter controlling how dramatic the shading is (start with 4.0)
80| 
81| Output: 2048x2048 RGBA8 Image (same size as terrain image), where each tile's 32x32 pixel block has the same normal value (flat within each tile — variation comes from tile-to-tile differences).
82| 
83| ### Sprite2D Material Setup
84| 
85| Each chunk Sprite2D gets a `CanvasItemMaterial` with:
86| - `texture` = terrain image (existing)
87| - `normal_map` = normal map image (new)
88| - `light_mode` = default (responds to Light2D nodes)
89| 
90| This is all Godot needs to shade the terrain dynamically under the DirectionalLight2D.
91| 
92| ### Static Ambient Occlusion
93| 
94| Baked into the terrain image (not the normal map):
95| - For each tile, compute an AO factor from the surrounding elevation
96| - Valleys (elevation lower than average of 8 neighbors) get darkened by 5-15%
97| - Ridges (elevation higher than average) get lightened by 3-8%
98| - This provides base depth even without the dynamic light
99| 
100| ## Component 3: Global Ambient Tint
101| 
102| A `CanvasModulate` node applies a color tint to the entire scene.
103| 
104| | Period | Color | Purpose |
105| |--------|-------|---------|
106| | Night (20:00-5:00) | (0.15, 0.15, 0.3) | Dark blue atmosphere |
107| | Dawn (5:00-7:00) | Lerp → (1.0, 0.9, 0.85) | Warm morning transition |
108| | Day (7:00-17:00) | (1.0, 1.0, 0.95) | Neutral, slightly warm |
109| | Golden hour (17:00-18:00) | Lerp → (1.0, 0.85, 0.6) | Amber evening |
110| | Dusk (18:00-20:00) | Lerp → (0.15, 0.15, 0.3) | Fade to night |
111| 
112| These values come from the existing `DayNightCycle.get_ambient_color()` method, which already implements similar logic. We'll refine the exact values to work well with the DirectionalLight2D.
113| 
114| ## Component 4: Building Light Occlusion (Future-Ready)
115| 
116| Not implemented in this phase, but the system design accommodates it:
117| 
118| - Wall tiles → `LightOccluder2D` polygons (block directional + point lights)
119| - Window tiles → no occluder (light passes through)
120| - Door tiles → conditional occluder (closed = block, open = pass)
121| - Interior tiles without light sources are naturally dark
122| - The building layer (Layer 3) will add occluders when it's built
123| 
124| No code needed now. The DirectionalLight2D and normal map system work correctly whether occluders exist or not.
125| 
126| ## Component 5: Point Light API (Future-Ready)
127| 
128| Not implemented in this phase. When the object/building systems are built:
129| 
130| - Torches, campfires, hearths, lanterns = `PointLight2D` nodes
131| - API: `create_light(world_pos: Vector2, color: Color, radius: float, energy: float, flicker: bool) -> Light2D`
132| - Flicker = small random energy variation per frame
133| - Managed by a LightManager that pools and recycles Light2D nodes (don't create/destroy per chunk)
134| 
135| No code needed now.

155| ## Component 7: Integration Points
156| 
157| ### CleanWorld.tscn Changes
158| - Add `DayNightCycle` instance (tick it in `_process`)
159| - Add `DirectionalLight2D` child node
160| - Add `CanvasModulate` child node
161| - Add lighting update logic in `_process`: read time → set light angle/color/height/energy → set modulate color
162| - Add `T` key handler for test mode toggle
163| 
164| ### NativeChunkCompiler Changes
165| - New method: `build_chunk_image_with_normals()` returns Dictionary `{"image": Image, "normal_map": Image}` — keeps the old method signature intact for backward compatibility
166| - Add static AO baking into the terrain image (darken/lighten pixels based on neighbor elevation average)
167| - Normal map generation in the same pass as terrain image (reuses elevation data already in scope)
168| 
169| ### ChunkStreamer Changes
170| - When displaying a chunk, create a `CanvasItemMaterial` with both terrain texture and normal map
171| - Assign material to the chunk's Sprite2D
172| 
173| ### TileMapTerrainRenderer Changes
174| - `display_chunk_image` accepts both terrain and normal map images
175| - Creates material, assigns textures, sets light_mode
176| 
177| ## Performance
178| 
179| - Normal map generation: ~0.5ms per chunk (same loop as elevation, just encoding)
180| - AO baking: ~0.2ms per chunk (8-neighbor average, one pass)
181| - DirectionalLight2D + CanvasModulate: GPU-side, no CPU cost per frame
182| - Memory: +16MB for normal maps across 49 loaded chunks (2048x2048x4 bytes each) — acceptable
183|
