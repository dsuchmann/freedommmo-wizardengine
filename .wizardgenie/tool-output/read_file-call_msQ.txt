1| # Performance Infrastructure Spec
2| 
3| > Established 2026-05-26. Three-layer performance foundation for FreedomMMO.
4| 
5| ## Problem
6| 
7| GDScript is interpreted (~100x slower than native). A simple 4096-tile loop takes 30-50ms. The RTX 3090 sits idle. This blocks every future system — terrain, NPCs, combat, lighting, particles. Must fix now before building more.
8| 
9| ## Three Stages (each independently valuable)
10| 
11| ### Stage 1: GDExtension C++ Foundation
12| 
13| **Goal:** Move chunk compilation and image building to C++. Establish the build pipeline that all future native code uses.
14| 
15| **Scope:**
16| - Set up GDExtension project structure (SCons/CMake, godot-cpp bindings)
17| - Port `ElevationLayer.compile()` to C++ (noise evaluation loop — biggest bottleneck)
18| - Port `build_chunk_image()` to C++ (4096 tile blits)
19| - Port `BiomeLayer.compile()` and `ClimateLayer.compile()` to C++
20| - GDScript calls the C++ class the same way it calls the GDScript class (drop-in replacement)
21| - Verify: chunk compilation < 1ms, image building < 1ms
22| 
23| **Deliverable:** Chunks compile and render with zero perceptible cost. Walking and teleporting are butter smooth.
24| 
25| **Validation:** Walk across 20+ chunk boundaries with FPS counter visible. No drops below 55fps.
26| 
27| ---
28| 
29| ### Stage 2: Python GPU Batch Pipeline
30| 
31| **Goal:** Adapt the existing `python_generator_gpu.py` (CuPy/CUDA on RTX 3090) for batch terrain pre-generation.
32| 
33| **Scope:**
34| - Adapt the Python GPU generator to output our ChunkCache binary format (not the old 512x512 region format)
35| - Accept overmap noise parameters so generated chunks match the overmap
36| - Generate overmap itself on GPU (41M pixels in seconds, not 30 seconds)
37| - Batch mode: pre-generate a spiral of chunks around a position (e.g., 100x100 = 10K chunks)
38| - Godot calls Python as a background process, polls for completion, loads results from ChunkCache
39| 
40| **Deliverable:** `python tools/generate_world.py --seed 42 --center 0,0 --radius 50` pre-generates 10K chunks in under 60 seconds. Godot loads them instantly from cache.
41| 
42| **Validation:** Teleport anywhere in pre-generated area. Instant terrain, no compilation needed.
43| 
44| ---
45| 
46| ### Stage 3: Compute Shader Framework
47| 
48| **Goal:** Set up Godot RenderingDevice compute shaders for real-time GPU work. Start with terrain, extend to lighting/particles later.
49| 
50| **Scope:**
51| - Create compute shader framework (load GLSL, create pipeline, dispatch, read results)
52| - Port terrain noise evaluation to GLSL compute shader (64x64 tiles = 4096 GPU threads)
53| - Port chunk image building to compute shader (read tile atlas, write chunk image)
54| - Framework for future shaders: lighting accumulation, water simulation, particle fields, fog density
55| 
56| **Deliverable:** Real-time chunk generation on GPU. Compile + render a chunk in < 0.5ms.
57| 
58| **Validation:** Disable ChunkCache, walk continuously. Chunks generate and render in real-time with no frame drops.
59| 
60| ---

62| ## Execution Order
63| 
64| ```
65| Stage 1 (GDExtension C++)
66|   ↓ validates: smooth streaming, build pipeline works
67| Stage 2 (Python GPU batch)
68|   ↓ validates: pre-generation, overmap consistency
69| Stage 3 (Compute shaders)
70|   ↓ validates: real-time GPU generation, framework for lighting/particles
71| ```
72| 
73| Each stage is a separate session. Each produces a working, testable improvement. No stage depends on the others being complete — they're complementary, not sequential.
74| 
75| ## What NOT to Build
76| 
77| - Don't port game logic (NPC AI, dialogue, quests) to C++ yet — GDScript is fine for logic that runs once per frame
78| - Don't build the lighting/particle shaders yet — just the framework
79| - Don't optimize the overmap generator yet — it runs once and caches
80| - Don't pre-generate the entire 41M chunk world — just the tools to do it incrementally
