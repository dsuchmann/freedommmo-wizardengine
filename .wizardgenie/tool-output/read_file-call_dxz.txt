3070| # Runtime Compositor Spec — Cel-Animation Tile Rendering
3071| 
3072| **Date:** 2026-05-26
3073| **Status:** Draft
3074| **Scope:** How Godot stacks, animates, and state-transitions the layered tile system at runtime.
3075| 
3076| ## Architecture Overview
3077| 
3078| Each visible tile on screen is a stack of up to 5 transparent layers composited via z-ordered rendering. A TileStateManager tracks the current state of every tile and tells the compositor which frame set to use.
3079| 
3080| ```
3081| Player walks through grass:
3082|   L5: [atmospheric - pollen drifting]        z=4
3083|   L4: [scatter - pebbles]                    z=3
3084|   L3: [vegetation - grass DISTURBED frame]   z=2  ← state-driven swap
3085|   L2: [detail - root pattern]                z=1
3086|   L1: [base - dirt ground]                   z=0
3087| ```
3088| 
3089| ## Tile State Machine
3090| 
3091| Each tile position (world x, y) has a state. States are driven by game events.
3092| 
3093| ### State Categories
3094| 
3095| States map to biome visual languages — the biomes themselves are the vocabulary for states:
3096| 
3097| | State | Visual Source | Trigger Examples |
3098| |-------|-------------|-----------------|
3099| | **pristine** | Native biome | Default |
3100| | **disturbed** | Native biome (variant frames) | Player/NPC walks through |
3101| | **trampled** | Native biome (worn variant) | Heavy foot traffic, paths form |
3102| | **dug** | Exposed earth/subterrain | Dig action, mining |
3103| | **burning** | Volcanic visual language | Fire spell, torch, wildfire spread |
3104| | **burned/scorched** | Volcanic + desert (ash, char) | After fire extinguishes |
3105| | **frozen** | Tundra/arctic visual language | Ice spell, winter event, altitude |
3106| | **wet** | Ocean/swamp visual language | Rain, flooding, water spell |
3107| | **cursed/corrupted** | Mystic visual language (dark variant) | Dark magic, undead presence |
3108| | **enchanted** | Mystic visual language (light variant) | Blessing, magical ward |
3109| | **decaying/undead** | Swamp visual language (rot, ooze) | Necromancy, blight |
3110| | **growing/fertile** | Forest/grassland lush variant | Growth spell, spring, fertilize |
3111| | **dry/drought** | Desert visual language | Heat, no rain, curse |
3112| 
3113| **Key insight:** Biome L2-L5 assets double as state overlays for other biomes. A "frozen" grassland tile uses tundra's L2 (frost patterns) overlaid on grassland's L1 (base ground). A "burning" forest tile uses volcanic's L3 (embers/cracks) overlaid on forest's L1.
3114| 
3115| This means generating biome assets also generates state assets. Efficiency multiplier.
3116| 
3117| ### State Transitions
3118| 
3119| ```gdscript
3120| # State machine per tile
3121| enum TileState {
3122|     PRISTINE, DISTURBED, TRAMPLED, DUG,
3123|     BURNING, BURNED, FROZEN, WET,
3124|     CURSED, ENCHANTED, DECAYING, GROWING, DRY
3125| }
3126| 
3127| # Each state has: entry_frames, loop_frames, exit_frames, duration (-1 = persistent)
3128| # Transitions: PRISTINE → DISTURBED (3s) → RECOVERING → PRISTINE
3129| #              PRISTINE → BURNING (5s) → BURNED (persistent)
3130| #              PRISTINE → FROZEN (persistent until thaw event)
3131| ```
3132| 
3133| ### State Layer Mapping
3134| 
3135| When a tile enters a non-pristine state, the compositor replaces specific sub-layers:
3136| 
3137| | State | L1 (Base) | L2 (Detail) | L3 (Vegetation) | L4 (Scatter) | L5 (Atmospheric) |
3138| |-------|-----------|-------------|-----------------|--------------|-------------------|
3139| | pristine | Native | Native | Native | Native | Native |
3140| | disturbed | Native | Native | Native (sway frame) | Native (shifted) | Native |
3141| | burning | Native (darken) | Volcanic L2 | Volcanic L3 (flames) | Remove | Volcanic L5 (smoke) |
3142| | frozen | Native | Tundra L2 (frost) | Tundra L3 (ice coat) | Arctic L4 (ice shards) | Arctic L5 (snow) |
3143| | cursed | Native (desaturate) | Mystic L2 (dark) | Mystic L3 (dark crystal) | Mystic L4 | Mystic L5 (dark particles) |
3144| | wet | Native | Ocean L2 (puddles) | Native (droop frame) | Native | Swamp L5 (mist) |
3145| | decaying | Native (darken+green) | Swamp L2 (rot) | Swamp L3 (dead vines) | Swamp L4 (bones) | Swamp L5 (miasma) |
3146| | growing | Native | Forest L2 (moss) | Forest L3 (sprouts) | Native | Grassland L5 (pollen) |
3147| | dry | Desert L1 (cracked) | Desert L2 (cracks) | Remove | Desert L4 (dust) | Desert L5 (heat haze) |
3148| 
3149| ## Compositor Node Architecture
3150| 
3151| ```
3152| ChunkRenderer (Node2D, per chunk)
3153|   ├─ L1_Base (Sprite2D, z=0)
3154|   ├─ L2_Detail (Sprite2D, z=1)
3155|   ├─ L3_Vegetation (Sprite2D, z=2)
3156|   ├─ L4_Scatter (Sprite2D, z=3)
3157|   └─ L5_Atmospheric (Sprite2D, z=4)
3158| ```
3159| 
3160| For Phase 1, each layer is a single Image composited from 64x64 Wang tiles (same as current chunk image approach). The chunk streamer builds 5 images per chunk instead of 1.
3161| 
3162| For state changes, only the affected layer images need to be rebuilt for the affected tiles — not the entire chunk.
3163| 
3164| ## Animation System
3165| 
3166| ### Frame-Swap Animation (Event-Driven)
3167| 
3168| Each layer can have multiple frames. Frames are swapped based on events, not timers:
3169| 
3170| ```gdscript
3171| # Player proximity triggers vegetation sway
3172| func _on_player_moved(player_pos: Vector2):
3173|     var tile_pos = world_to_tile(player_pos)
3174|     for nearby_tile in get_tiles_in_radius(tile_pos, 2):
3175|         var dist = tile_pos.distance_to(nearby_tile)
3176|         var sway_frame = compute_sway_frame(dist, player_velocity)
3177|         set_tile_state(nearby_tile, TileState.DISTURBED, {"frame": sway_frame})
3178| ```
3179| 
3180| ### Ambient Animation (Timer-Based, Low Priority)
3181| 
3182| Some layers have slow ambient cycles — water ripples, lava glow pulse, mystic shimmer. These use timers but at low frequency (2-4 FPS) to keep the pixel art feel:
3183| 
3184| ```gdscript
3185| # Ambient water ripple — cycles through 4 frames every 2 seconds
3186| func _tick_ambient():
3187|     if biome in [OCEAN, LAKE, RIVER, SWAMP]:
3188|         L1_frame = (L1_frame + 1) % 4  # Slow cycle
3189| ```
3190| 
3191| ## Performance Budget
3192| 
3193| - **Max 5 Sprite2D per chunk** (one per layer)
3194| - **Image rebuilds**: Only when tile states change, not every frame
3195| - **Ambient animation**: Batched — all water tiles in a chunk swap frame simultaneously
3196| - **State tracking**: PackedByteArray per chunk (64x64 = 4096 bytes, one byte per tile)
3197| - **Memory**: 5 Images per chunk × 49 loaded chunks = 245 Images. At 2048x2048 RGBA8 = ~4MB each = ~1GB. May need to skip L5 atmospheric for distant chunks.
3198|

3224| ## Core Concept
3225| 
3226| The world has multiple Z-levels sharing the same XY coordinate space. The surface is Z=0. Below it are cave networks, basements, dungeons, and underground settlements at Z=-1 and deeper. Movement between levels is seamless — walk into a cave entrance, descend stairs, fall into a pit. No loading screens.
3227| 
3228| ## Z-Level Architecture
3229| 
3230| ```
3231| Z-Level  0: Surface (current — terrain, buildings, objects, NPCs)
3232| Z-Level -1: Shallow underground (caves, basements, shallow dungeons)
3233| Z-Level -2: Deep underground (deep caves, large dungeons)
3234| Z-Level -3: Abyssal (deep networks, rare, dangerous)
3235| ```
3236| 
3237| Each Z-level uses the same ChunkData structure, same chunk streaming, same coordinate system. The player has a `current_z_level` property. The renderer displays whichever level the player is on.

3342| # World Biome System Design
3343| 
3344| **Date:** 2026-05-26  
3345| **Status:** Approved  
3346| **Scope:** Overmap macro feature placement + chunk-level biome-contextual terrain + 18-biome enum alignment
3347| 
3348| ## Problem
3349| 
3350| The current world generation produces biomes from 4 independent noise fields (elevation, ridge, temperature, moisture) with weak coupling. This causes:
3351| 
3352| 1. **Arctic never appears** — temperature penalty from elevation is only `h * 0.15`, so t < 0.15 is practically impossible
3353| 2. **Volcanic never appears** — defined in enum but zero code assigns it
3354| 3. **Mystic doesn't exist** — not in codebase at all
3355| 4. **Lake/River never appear** — in enum but no assignment logic
3356| 5. **No geographic structure** — the world has no intentional relationships between biomes. No mountain range, no volcanic region, no mystic domains. Just random noise soup.
3357| 6. **Movement breaks** on certain terrain after teleport (ocean, extreme slopes)
3358| 
3359| ## Approach: Procedural Macro Features + Noise Micro Detail
3360| 
3361| **Macro layer (overmap):** Procedural feature placement that guarantees geographic structure. Features are derived from noise (not hardcoded), so every seed produces a different but always-coherent world.
3362| 
3363| **Micro layer (chunk):** Noise-driven detail with biome-contextual variance — cliffs in mountains, dunes in desert, caldera in volcanic, crystalline ridges in mystic, etc.
3364| 
3365| ## The 18 Biomes
3366| 
3367| ```
3368| OCEAN=0, BEACH=1, GRASSLAND=2, FOREST=3, DENSE_FOREST=4, DESERT=5,
3369| SAVANNA=6, STEPPE=7, TUNDRA=8, TAIGA=9, MOUNTAINS=10, SWAMP=11,
3370| TROPICAL_FOREST=12, VOLCANIC=13, ARCTIC=14, LAKE=15, RIVER=16, MYSTIC=17
3371| ```
3372| 
3373| All 18 must be assignable by both the C++ chunk compiler and the GDScript overmap generator. One classification function, two callers.
3374| 
3375| ## Macro Feature Placement
3376| 
3377| At world generation time, scan the base noise fields to derive macro features. These are stored as modifier fields (640x640 float arrays) alongside the overmap image.
3378| 
3379| ### Feature Anchors
3380| 
3381| | Feature | Derivation Method | Approximate Size |
3382| |---------|-------------------|------------------|
3383| | **Mountain Spine** | Connected ridge of highest `ridge_noise` values cutting across the map | Large — bisects the world |
3384| | **Arctic Zones** | Peaks of the mountain spine where elevation > 0.85 | Moderate — several clusters along spine |
3385| | **Volcanic Hotspot** | Single point where `ridge_noise` is highest AND base temperature is warmest | Small-moderate, radiating outward (radius ~15-20 overmap pixels) |
3386| | **Mystic Domains** | 3-4 locations where new `magic_noise` exceeds threshold (> 0.8) | Moderate, self-contained (radius ~8-12 overmap pixels each) |
3387| | **Tropical Forest** | Largest contiguous region where temperature > 0.65 AND moisture > 0.55 | One massive zone |
3388| | **Savanna** | Adjacent to tropical forest, drier side (moisture 0.2-0.5) | One major zone |
3389| | **Swamp** | Low elevation + high moisture, moisture boost applied near volcanic region | Wraps around volcanic border |
3390| | **Lakes** | 5-8 local elevation minima in land areas | Radius 3-5 overmap pixels each |
3391| | **Rivers** | Downhill gradient trace from each lake toward ocean or another lake | Width 1 overmap pixel, expands to 3-5 tiles at chunk level |
3392| 
3393| ### Biome Adjacency Graph
3394| 
3395| ```
3396| Ocean → Beach → Grassland ──→ Forest → Dense Forest → Swamp ──→ Volcanic
3397|                     │                                              ↑
3398|                     ├──→ Desert → Savanna → Steppe ────→ Mountains ┤
3399|                     │                  │                     │
3400|                     │                  └→ Tropical Forest    └→ Arctic (peaks)
3401|                     │
3402|                     └──→ Tundra → Taiga
3403| 
3404| Lakes: scattered throughout all land biomes
3405| Rivers: flow downhill from lakes
3406| Mystic: 3-4 independent pockets, any land context
3407| ```
3408| 
3409| ### Modifier Field Computation
3410| 
3411| ```
3412| 1. Generate base noise fields (elevation, ridge, temp, moisture, magic)
3413| 2. Strengthen couplings:
3414|    - Temperature penalty from elevation: t -= h * 0.45 (was 0.15)
3415|    - This naturally makes mountain peaks arctic
3416| 3. Scan ridge noise to find mountain spine (connected high-ridge path)
3417| 4. Find volcanic hotspot (max ridge × max temp intersection)
3418| 5. Find 3-4 mystic domains (magic noise peaks > 0.8)
3419| 6. Find 5-8 lake basins (local elevation minima in land areas)
3420| 7. Trace rivers downhill from lakes
3421| 8. Compute modifier fields (all 640×640):
3422|    - volcanic_influence: radial falloff from hotspot
3423|    - mystic_influence: radial falloff from each domain center
3424|    - swamp_pull: moisture boost near volcanic region
3425|    - lake_mask: boolean lake coverage
3426|    - river_mask: boolean river paths
3427| 9. Store modifiers as binary data alongside overmap PNG
3428| 10. Biome classification applies modifiers:
3429|     - VOLCANIC where volcanic_influence > 0.5
3430|     - MYSTIC where mystic_influence > 0.5
3431|     - LAKE where lake_mask is true
3432|     - RIVER where river_mask is true
3433|     - swamp_pull boosts local moisture to create SWAMP adjacency near volcanic
3434|     - Standard temp/moisture/elevation rules handle everything else
3435| ```

3476|

3478| - Biome transitions within a chunk use existing Wang tileset blending

3561| # Elevation Cliff Rendering System
3562| 
3563| **Date:** 2026-05-27
3564| **Status:** Approved
3565| **Scope:** Replace flat tile rendering with continuous elevation-driven cliff layers, where terrain height is expressed as stacked cliff walls and elevated surface tiles.
3566| 
3567| ## Problem
3568| 
3569| The current hypergraph terrain system selects the correct surface (grass, rock, snow) based on elevation, but renders everything on a single flat plane. A mountain peak and a valley floor sit at the same visual Y position — only the tile color differs. There is no visual topography: no cliffs, no height, no sense of the landscape rising and falling. The world looks like a painted carpet, not terrain.
3570| 
3571| ## Core Model
3572| 
3573| Elevation is continuous (0.0–1.0). Every tile's elevation maps to a visual Y-offset in pixels:
3574| 
3575| ```
3576| visual_y_offset = (elevation - SEA_LEVEL) * PIXELS_PER_UNIT
3577| ```
3578| 
3579| Where `SEA_LEVEL = 0.38` and `PIXELS_PER_UNIT = 512` (tunable). This means:
3580| - A tile at elevation 0.50 renders 61px above sea level
3581| - A tile at elevation 0.80 renders 215px above sea level
3582| - A tile at elevation 1.00 renders 317px above sea level
3583| - A tile at elevation 0.38 (sea level) renders at Y-offset 0
3584| 
3585| There are no fixed "levels" or "buckets." Every tile sits at its exact elevation. The number of visual layers in any given area is determined entirely by the terrain — a flat plain has zero cliff faces, a mountain might have cliff walls hundreds of pixels tall.
3586| 
3587| ## Cliff Walls
3588| 
3589| When adjacent tiles differ in elevation, the gap between them is filled with a **cliff wall** — a vertical textured face visible from the top-down camera.
3590| 
3591| ### Which edges get cliff walls
3592| 
3593| Cliff walls render on the **south and east** edges of elevated tiles. These are the sides visible to a top-down camera with a slight southward perspective (standard for 2D RPGs). North and west edges are occluded by the tile's own surface.
3594| 
3595| For a tile at (x, y) with elevation E:
3596| - **South wall:** if tile at (x, y+1) has elevation E_south < E, draw a cliff wall of height `(E - E_south) * PIXELS_PER_UNIT` pixels on the south edge
3597| - **East wall:** if tile at (x+1, y) has elevation E_east < E, draw a cliff wall of height `(E - E_east) * PIXELS_PER_UNIT` pixels on the east edge
3598| 
3599| ### Cliff wall composition
3600| 
3601| Each cliff wall is assembled from three tile pieces:
3602| 
3603| | Piece | Size | Purpose |
3604| |-------|------|---------|
3605| | `cliff_top` | 32×8px | Overhang where surface meets wall — grass roots, dirt edge, snow lip |
3606| | `cliff_mid` | 32×32px | Repeating wall face — stone layers, dirt strata, ice. Tiles vertically. |
3607| | `cliff_bot` | 32×8px | Base where wall meets lower ground — shadow, rubble, moss |
3608| 
3609| For a cliff wall of height H pixels:
3610| 1. Draw `cliff_top` (8px)
3611| 2. Draw `cliff_mid` repeated `floor((H - 16) / 32)` times (middle fill)
3612| 3. Draw remaining fractional `cliff_mid` height (partial tile)
3613| 4. Draw `cliff_bot` (8px)
3614| 
3615| Minimum cliff height to render: 4px (below this, the elevation difference is too small to see).
3616| 
3617| ### Cliff face variants per surface
3618| 
3619| Each of the 13 surface types needs its own cliff face set, because the wall should match the terrain it's part of:
3620| 
3621| | Surface | Cliff face appearance |
3622| |---------|----------------------|
3623| | lush_grass | Dirt/soil with grass roots hanging over the top edge |
3624| | golden_sand | Sandy crumbling cliff face with exposed rock |
3625| | forest_floor | Dark earth with tree roots and moss |
3626| | grey_rock | Layered stone with mineral veins |
3627| | snow | Packed snow over ice with frozen dirt |
3628| | frozen_earth | Permafrost layers with ice crystals |
3629| | glacial_ice | Blue-white ice face with pressure cracks |
3630| | volcanic_rock | Dark basalt with glowing lava veins |
3631| | swamp_mud | Wet mud layers with standing water seeping out |
3632| | dry_grass | Rocky soil with sparse root systems |
3633| | dark_humus | Very dark decomposing layers with fungal growth |
3634| | ocean_water | (no cliff face — water fills from below) |
3635| | mystic_crystal | Glowing purple crystal cross-section |
3636| 
3637| That's 12 cliff face sets × 3 pieces = 36 cliff tiles, plus corner and diagonal variants are required for V1:
3638| 
3639| **Corner variants** (where two cliff walls meet at 90°):
3640| - Inner corner (concave) — south wall meets east wall from adjacent tiles
3641| - Outer corner (convex) — cliff wraps around a protruding ledge
3642| 
3643| **Diagonal variants** (where elevation changes diagonally):
3644| - SW-NE diagonal cliff face
3645| - SE-NW diagonal cliff face
3646| 
3647| Each surface needs: 3 straight pieces + 2 corner pieces + 2 diagonal pieces = **7 cliff tiles per surface**.
3648| 
3649| Total: 12 surfaces × 7 pieces = **84 cliff tiles** to generate via PixelLab.
3650| 
3651| ## Render Order
3652| 
3653| Tiles render back-to-front using a **painter's algorithm** sorted by (world_y ascending, elevation ascending):
3654| 
3655| 1. **Water plane** at sea-level Y-offset (if any water visible in the viewport)
3656| 2. For each row (north to south):
3657|    a. For each tile in the row (sorted by elevation ascending):
3658|       - Draw cliff walls (south and east) descending from this tile to lower neighbors
3659|       - Draw surface tile at this tile's visual Y-offset
3660| 3. Higher tiles naturally occlude lower tiles' cliff walls
3661| 
3662| This ensures:
3663| - Cliffs face the camera (south-facing walls visible)
3664| - Higher terrain covers lower terrain's walls
3665| - Water sits at the bottom of basins
3666| 
3667| ## Water
3668| 
3669| Water is the floor at elevation 0.38 (sea level):
3670| 
3671| - Any tile with elevation < SEA_LEVEL is submerged — the water surface renders at the sea-level Y plane
3672| - The ocean_water surface tile renders ON the water plane for submerged tiles
3673| - Coastlines are natural cliff faces: land tiles at elevation > SEA_LEVEL have cliff walls descending to the water plane
3674| - Lakes are terrain depressions below sea level
3675| - Rivers are narrow channels cut below surrounding terrain elevation
3676| 
3677| This naturally fixes the overmap/render mismatch — areas the overmap shows as blue (low elevation) will visually be water basins with terrain rising out of them.
3678| 
3679| ## Camera
3680| 
3681| - **Follows player** at their visual position (grid position + elevation Y-offset)
3682| - **Zoom-out at height**: camera zoom decreases slightly as player elevation increases, giving a wider view from mountaintops. Scale factor: `zoom = base_zoom - (elevation - SEA_LEVEL) * ZOOM_ELEVATION_FACTOR`
3683| - **Bokeh/depth-of-field**: terrain below the player's current elevation gets progressively blurred. Already partially implemented — extend to use the new elevation offset system.
3684| 
3685| ## Player Movement (Deferred)
3686| 
3687| Not in scope for this spec, but the elevation system enables:
3688| 
3689| - **Walking**: traverse gentle slopes where adjacent tile elevation difference < MAX_WALK_SLOPE
3690| - **Climbing**: BotW/Genshin-style wall climbing on cliff faces (stamina-based)
3691| - **Gliding**: jump off cliff edges, trade height for horizontal distance
3692| - **Swimming**: enter water at sea level
3693| 
3694| These will be designed in a separate spec.
3695| 
3696| ## PIXELS_PER_UNIT Tuning
3697| 
3698| The single most important constant. Starting value: **512**.
3699| 
3700| | Scenario | Elevation diff | Visual height |
3701| |----------|---------------|---------------|
3702| | Gentle slope | 0.02 | 10px (subtle step) |
3703| | Small hill | 0.05 | 26px (visible rise) |
3704| | Significant hill | 0.15 | 77px (~2.4 tile heights) |
3705| | Mountain from plains | 0.40 | 205px (~6.4 tile heights) |
3706| | Full sea-to-peak | 0.62 | 317px (~10 tile heights) |
3707| 
3708| This is data, not code. Tunable at runtime for visual QA.
3709|

3711| 
3712| ### Modified Components
3713| 
3714| **`LayeredChunkRenderer`** — Major rewrite. Instead of painting one flat image per chunk, it now:
3715| 1. Calculates visual Y-offset per tile from elevation
3716| 2. Creates cliff wall sprites between tiles with different elevations
3717| 3. Renders surface tiles at their elevated Y positions
3718| 4. Sorts everything back-to-front for correct occlusion
3719| 
3720| **`CleanWorld.gd`** — Camera system updates:
3721| - Track player elevation for Y-offset
3722| - Zoom-out factor based on elevation
3723| - Bokeh intensity based on elevation delta between player and terrain
3724| 
3725| ### New Components
3726| 
3727| **`CliffTileLoader`** — Loads cliff face tile assets (cliff_top, cliff_mid, cliff_bot per surface type). Similar to LayeredTilesetLoader but for vertical cliff tiles.
3728| 
3729| **`ElevationRenderer`** — Core rendering logic extracted from LayeredChunkRenderer. Given a chunk's elevation data, produces the sorted draw list of (surface tiles + cliff walls + water) with correct Y-offsets and z-ordering.

3746| ## Performance Considerations
3747| 
3748| Each chunk is 64×64 = 4,096 tiles. In the worst case (mountainous terrain), each tile could have south and east cliff walls. That's up to 8,192 cliff wall sprites per chunk plus 4,096 surface sprites = 12,288 draw calls per chunk. With a 7×7 chunk grid visible, that's up to 600K draw calls.
3749| 
3750| This will require optimization:
3751| - **Batch cliff walls** into chunk-level images (like the current surface image approach)
3752| - **Skip tiny cliffs** below the 4px minimum threshold
3753| - **LOD**: at far zoom, render cliff walls as simple dark lines instead of textured tiles
3754| - **Frustum culling**: only render cliff walls visible in the viewport
3755| 
3756| The GDScript prototype will be slow. This is a strong candidate for C++ migration after the visual design is validated.

3759| # Elevation Hypergraph Terrain System
3760| 
3761| **Date:** 2026-05-27
3762| **Status:** Approved
3763| **Scope:** Replace flat biome-based tile selection with elevation-driven surface gradients and hypergraph transitions.
3764| 
3765| ## Problem
3766| 
3767| The current terrain renderer picks one tileset per biome and tiles it flat. A grassland biome looks the same at elevation 0.35 as it does at 0.70. Mountains are a distinct biome rather than the natural result of high elevation within any biome. Biome transitions happen abruptly at classification boundaries rather than flowing naturally with the landscape.
3768| 
3769| ## Core Concept: Elevation Gradients + Surface Hypergraph
3770| 
3771| Each biome defines an **elevation gradient** — an ordered list of surfaces that appear as elevation increases. A **surface** is a distinct terrain appearance (e.g., "lush green grass," "grey mountain stone," "snow"). Surfaces are shared across biomes, forming a many-to-many **hypergraph**: the same "grey rock" surface appears in grassland's gradient at high elevation and in tundra's gradient at mid elevation.
3772| 
3773| At each tile, elevation at the 4 corners determines which surface(s) appear. When adjacent corners cross an elevation threshold, a Wang transition tileset blends between the two surfaces. This uses the exact same 16-tile Wang autotiling infrastructure that already exists.
3774| 
3775| ## Surfaces (Hypergraph Nodes)
3776| 
3777| 13 unique terrain surfaces, each backed by a 16-tile Wang self-tileset:
3778| 
3779| | Surface ID | Description | Source |
3780| |---|---|---|
3781| | `ocean_water` | Blue water with gentle waves | Existing L1: ocean |
3782| | `golden_sand` | Sandy beach/desert surface | Existing L1: beach, desert |
3783| | `lush_grass` | Green grass with individual blades | Existing L1: grassland |
3784| | `dry_grass` | Windswept sparse grass on rocky soil | Existing L1: steppe |
3785| | `forest_floor` | Dark earth with leaves, moss, twigs | Existing L1: forest |
3786| | `dark_humus` | Very dark decomposing leaf carpet | Existing L1: dense_forest |
3787| | `swamp_mud` | Murky mud with standing water | Existing L1: swamp |
3788| | `grey_rock` | Mountain stone with moss, mineral veins | Existing L1: mountains |
3789| | `volcanic_rock` | Dark rock with glowing lava cracks | Existing L1: volcanic |
3790| | `frozen_earth` | Permafrost tundra soil | Existing L1: tundra |
3791| | `glacial_ice` | Blue-white ice with pressure cracks | Existing L1: arctic |
3792| | `snow` | White snow cover | Existing L1: mountains (upper variant) |
3793| | `mystic_crystal` | Purple glowing crystal floor | Existing L1: mystic |
3794| 
3795| All 13 surfaces already exist as L1 base tilesets in `assets/catalog/terrain_v2/`. They need to be reorganized into a `surfaces/` directory but no regeneration is required.
3796| 
3797| ## Transitions (Hypergraph Edges)
3798| 
3799| Transition tilesets are needed between any two surfaces that are adjacent in at least one biome's elevation gradient, or across biome boundaries. Each is a standard 16-tile Wang tileset generated via PixelLab with `base_tile_id` chaining.
3800|
