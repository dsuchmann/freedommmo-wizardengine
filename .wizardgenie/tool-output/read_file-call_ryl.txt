1| # Overmap + Streaming Terrain Design
2| 
3| > Established 2026-05-25. Integrates the overmap navigation system with the deterministic WorldCompiler terrain pipeline.
4| 
5| ## Core Principle: Deterministic World From Seed
6| 
7| The entire world is defined by a single integer seed. The same seed + coordinates produce the exact same terrain on every client, every time. No server-side terrain storage needed. No pre-rendering needed. The seed IS the world.
8| 
9| - World seed: stored in `ServerConfig` (default: 42)
10| - World capacity: 6,400 × 6,400 chunks = ~41 million chunks
11| - Each chunk: 64×64 tiles at 32px = 2,048×2,048 pixels
12| - Total world: ~13 million pixels per side
13| - Walking time to cross: ~33 hours continuous
14| - Only ~25 chunks loaded at any time
15| 
16| ## 1. Overmap
17| 
18| A 6,400×6,400 pixel Image where each pixel represents one chunk. Generated by evaluating the elevation + climate noise functions at each chunk's center world coordinate. Pixel color encodes biome type.
19| 
20| ### Generation
21| - Sample elevation noise at `(chunk_x * 64 + 32, chunk_y * 64 + 32)` for each pixel
22| - Sample climate noise at the same position for temperature/precipitation
23| - Classify biome from elevation + climate (same thresholds as BiomeLayer)
24| - Set pixel color from BiomeLayer.biome_color()
25| - Total: 41M noise evaluations. Target: ~30 seconds.
26| - Cache result as PNG at `user://overmap_{seed}.png` for instant reload
27| 
28| ### Display
29| - TextureRect on a CanvasLayer overlay
30| - Press `M` to toggle open/close
31| - Red marker shows current player position (updated from player world pos / chunk pixel size)
32| - Click a pixel to teleport (see Section 3)
33| 
34| ### Biome Colors (same as BiomeLayer)
35| | Biome | Color |
36| |-------|-------|
37| | Ocean | Dark blue (0.1, 0.2, 0.5) |
38| | Beach | Tan (0.9, 0.85, 0.6) |
39| | Grassland | Green (0.4, 0.75, 0.3) |
40| | Forest | Dark green (0.15, 0.5, 0.15) |
41| | Desert | Sandy (0.85, 0.75, 0.45) |
42| | Mountains | Gray (0.55, 0.55, 0.55) |
43| | Tundra | White-blue (0.7, 0.75, 0.8) |
44| | Swamp | Murky green (0.3, 0.4, 0.25) |
45| 
46| ## 2. Chunk Streaming
47| 
48| ### Loaded Grid
49| - 5×5 grid of chunks around the player (25 chunks loaded)
50| - Each chunk rendered via TileMapTerrainRenderer onto shared TileMapLayer nodes
51| - Total visible area: 320×320 tiles = 10,240×10,240 pixels
52| 
53| ### Movement Detection
54| - Every frame, compute which chunk the player is in
55| - When player crosses 60% toward a grid edge, trigger loading of the next row/column in that direction
56| - Loading happens one chunk per frame via `await get_tree().process_frame`
57| 
58| ### Chunk Lifecycle
59| ```
60| Player approaches edge
61|   → ChunkStreamer._check_grid_expansion()
62|   → For each new chunk position:
63|       → ChunkCache.try_load(cx, cy)
64|         → HIT: deserialize ChunkData from binary, skip compilation
65|         → MISS: compile via two-phase pipeline (see below)
66|       → TileMapTerrainRenderer.register_chunk(chunk)
67|       → TileMapTerrainRenderer.render_chunk(chunk)
68|   → Unload chunks > 3 rows behind player:
69|       → TileMapTerrainRenderer.clear_chunk(cx, cy)
70|       → Remove from renderer._chunks dictionary
71| ```
72| 
73| ### Incremental Two-Phase Compilation
74| When streaming (not bulk-compiling), new chunks compile using neighbor context:
75| 
76| 1. **Phase 1**: ElevationLayer + OceanMaskLayer compile on the new chunk (uses world_seed noise — inherently seamless)
77| 2. **Edge propagation**: Copy ocean_distance values from already-compiled neighbor chunks' edges into the new chunk's border cells, then run local BFS inward. This replaces the global BFS with O(chunk_edge) work.
78| 3. **Phase 2**: ClimateLayer + BiomeLayer + VegetationLayer + CoastalLayer compile using the corrected ocean_distance data
79| 
80| This produces seamless terrain without needing all chunks compiled upfront.
81| 
82| ### Performance Budget
83| - Chunk compilation: ~50ms (GDScript)
84| - Chunk rendering: ~20ms (TileMapLayer.set_cell)
85| - At 1 chunk per frame (60fps): ~70ms per chunk = fine, no frame drops
86| - Streaming 5 new chunks (one row): ~5 frames = 83ms total
87| - Player walking speed: 3.4 tiles/sec = crosses a 64-tile chunk every ~19 seconds
88| - 19 seconds between row loads. Plenty of buffer.
89| 
90| ## 3. Click-to-Teleport
91| 
92| When overmap is open and player clicks:
93| 
94| 1. Map pixel (px, py) → chunk coordinates (px - 3200, py - 3200)
95| 2. Clear all loaded TileMapLayer cells
96| 3. Show "Traveling..." label
97| 4. Compile 5×5 grid around target chunk (~25 chunks, ~1.25 seconds)
98| 5. Teleport player to center of target chunk
99| 6. Close overmap, resume gameplay
100| 
101| Player position marker on overmap: `marker_pos = player_world_pos / (ChunkData.SIZE * TILE_SIZE)`
102| 
103| ## 4. Binary Chunk Cache
104| 
105| ### Format
106| ```
107| u32 magic (0x434B4E4B = "CHNK")
108| u16 version (1)
109| i32 chunk_x
110| i32 chunk_y
111| i32 world_seed
112| u16 size (64)
113| [PackedFloat32Array elevation — 4096 floats]
114| [PackedByteArray ocean_mask — 4096 bytes]
115| [PackedFloat32Array ocean_distance — 4096 floats]
116| [PackedFloat32Array temperature — 4096 floats]
117| [PackedFloat32Array precipitation — 4096 floats]
118| [PackedByteArray biome_id — 4096 bytes]
119| [PackedByteArray vegetation_density — 4096 bytes]
120| [PackedByteArray vegetation_species — 4096 bytes]
121| [PackedFloat32Array slope — 4096 floats]
122| ```
123| 
124| ### Storage
125| - Location: `user://chunks/{cx}_{cy}.bin`
126| - Size per chunk: ~70KB (mostly float arrays)
127| - 1000 cached chunks = ~70MB (reasonable)
128| - Seed validation: if cached chunk's world_seed doesn't match current seed, discard and recompile
129| 
130| ### Cache Policy
131| - Save after first compilation
132| - Load on revisit (skip compilation)
133| - Invalidate when world_seed changes
134| - No size limit — disk is cheap, player exploration is valuable
135| 
136| ## 5. File Architecture
137| 
138| | Component | File | Lines (est.) | Responsibility |
139| |-----------|------|-------------|----------------|
140| | CleanWorld.gd | Existing (~180 lines) | ~250 | Scene controller: player, camera, bokeh, overmap toggle, teleport |
141| | OvermapGenerator | `scripts/core/overmap_generator.gd` (new) | ~120 | Generate 6400×6400 Image from noise. Cache as PNG. |
142| | ChunkStreamer | `scripts/core/chunk_streamer.gd` (new) | ~200 | Manage 5×5 grid. Detect movement. Compile/load/unload chunks. |
143| | ChunkCache | `scripts/core/chunk_cache.gd` (new) | ~150 | Binary serialize/deserialize ChunkData. File I/O. |
144| | WorldCompiler | Existing | Unchanged | Compile chunks from layers |
145| | TileMapTerrainRenderer | Existing | Unchanged | Render chunks to TileMapLayers |
146| 
147| **Data flow:**
148| ```
149| Player moves → ChunkStreamer detects edge approach
150|   → ChunkCache.has(cx, cy)?
151|     → YES: ChunkCache.load() → skip compilation
152|     → NO: WorldCompiler two-phase compile → ChunkCache.save()
153|   → TileMapTerrainRenderer.render_chunk()
154|   → Unload distant chunks
155| 
156| Player presses M → OvermapGenerator.get_or_create() → display overlay
157| Player clicks overmap → CleanWorld._teleport_to(chunk_x, chunk_y)
158|   → Clear grid → compile 5×5 → render → teleport
159| ```
160| 
161| ## 6. What This Does NOT Include
162| 
163| - Rivers (need cross-chunk flow simulation — separate effort)
164| - Settlements, buildings, NPCs (Layers 2-7 — future work)
165| - Multiplayer synchronization (same seed = same world, but player positions need networking)
166| - Sound or music (future layer)
167| 
168| This spec covers ONLY: overmap generation, chunk streaming, click-to-teleport, and binary caching — all operating on the existing Layer -2 terrain pipeline.
