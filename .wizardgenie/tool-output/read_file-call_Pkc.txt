3960| ## Wang Index Computation
3961| 
3962| For each tile at (x, y):
3963| 
3964| 1. Sample elevation at 4 corners: TL(x,y), TR(x+1,y), BL(x,y+1), BR(x+1,y+1)
3965| 2. Look up biome at tile center from `chunk.biome_id`
3966| 3. Map each corner's elevation through the biome's gradient to get a surface
3967| 4. If all 4 corners → same surface: use self-tileset, wang_index from spatial hash
3968| 5. If corners span 2 surfaces: use transition tileset, wang_index from corner classification (4-bit: TL=bit0, TR=bit1, BL=bit2, BR=bit3, where 0=lower surface, 1=upper surface)
3969| 6. If corners span 3+ surfaces: clamp to the 2 most common surfaces
3970| 
3971| Cross-chunk corner sampling: when a corner falls outside the current chunk, look up elevation from the adjacent chunk via the chunk dictionary (already supported by ChunkStreamer).
3972|

4035| # Layer -1: Terrain Shading Design
4036| 
4037| **Date:** 2026-05-27
4038| **Status:** Approved
4039| **Scope:** Wire existing C++ normal maps + AO to rendering, add directional lighting, fix day/night transitions
4040| 
4041| ## Context
4042| 
4043| The elevation renderer stacks terrain at different Y-offsets, creating visible height. But there's no dynamic shading — no sense of sun direction, no slope highlighting, no ambient depth. The C++ `NativeChunkCompiler` already generates normal maps and baked AO, but they're not connected to rendering.
4044| 
4045| Day/night transitions have abrupt color snaps at 6:00 AM and golden hour→night due to piecewise linear interpolation with hard breakpoints.
4046| 
4047| ## Architecture
4048| 
4049| ### Approach: Hybrid (Godot Native Normals + AO)
4050| 
4051| 1. **Godot's built-in 2D lighting** handles sun/moon via DirectionalLight2D + normal maps
4052| 2. **C++ baked AO** provides static ambient depth (valleys dark, ridges bright) — always visible regardless of sun position
4053| 3. **DayNightCycle** drives all light parameters (angle, color, energy)
4054| 
4055| ### Components
4056| 
4057| #### 1. DirectionalLight2D (Sun + Moon)
4058| 
4059| Two `DirectionalLight2D` nodes, children of the scene root:
4060| 
4061| - **Sun light**: angle from `DayNightCycle.get_sun_angle()`, color from `get_sun_color()`, energy from `get_sun_energy()`. Active during day. Slopes facing the sun are bright, slopes facing away are dark.
4062| - **Moon light**: opposite angle, blue-white color `(0.4, 0.5, 0.85)`, energy from `get_moonlight_energy()`. Active during night. Subtle — provides directionality to moonlit terrain.
4063| 
4064| Both lights use `height = 0.6` for a moderate incidence angle that creates visible slope shading without extreme shadows.
4065| 
4066| #### 2. Normal Map Wiring
4067| 
4068| The C++ compiler already returns `{"image": terrain, "normal_map": normal_map}` from `build_chunk_image_with_normals()`.
4069| 
4070| For elevation sprites (created by `LayeredChunkRenderer.display_prerendered()`):
4071| - Create a `CanvasTexture` instead of a raw `ImageTexture`
4072| - Assign the terrain image as `diffuse_texture`
4073| - Assign the normal map as `normal_texture`
4074| - Godot's 2D lighting system automatically uses the normals for directional light response
4075| 
4076| For the elevation renderer's per-level sprites:
4077| - Generate a per-level normal map alongside the per-level terrain image in `ElevationRenderer.render_chunk()`
4078| - Use the same elevation data that's already available to compute normals: `nx = elev[left] - elev[right]`, `ny = elev[up] - elev[down]`, `nz = 1.0`, normalized and encoded as RGB
4079| 
4080| #### 3. AO Integration
4081| 
4082| The C++ compiler already bakes AO into the terrain image (valleys -15%, ridges +8%). This is sufficient for the base level. For elevation sprites, the darkened cliff walls (`_get_dark_tile`) serve as basic AO.
4083| 
4084| No additional AO overlay needed — the existing bake provides ambient depth.
4085| 
4086| #### 4. Day/Night Transition Fix
4087| 
4088| **Problem:** Piecewise linear lerps in `get_sun_color()` and `get_ambient_color()` create visible discontinuities ("knees") where two linear segments meet.
4089| 
4090| **Fix:** Replace all `lerp` calls with `smoothstep` interpolation:
4091| 
4092| ```gdscript
4093| func _smoothlerp(a: Color, b: Color, t: float) -> Color:
4094|     var st = t * t * (3.0 - 2.0 * t)  # smoothstep
4095|     return a.lerp(b, st)
4096| ```
4097| 
4098| **Extended time boundaries:**
4099| 
4100| | Period | Current | New |
4101| |--------|---------|-----|
4102| | Dawn start | 4:30 | 4:00 |
4103| | Dawn end | 7:00 | 8:00 |
4104| | Golden start | 15:00 | 14:30 |
4105| | Sunset | 18:30 | 19:00 |
4106| | Dusk end | 20:30 | 21:30 |
4107| 
4108| Apply to both `get_sun_color()` and `get_ambient_color()` with matching boundaries so they transition in sync.
4109| 
4110| #### 5. Moonlight Spotlight Fix
4111| 
4112| Current: `texture_scale = 1.0` (reduced from 14.0). Still visible as a distinct circle.
4113| 
4114| Fix:
4115| - `texture_scale = 1.2` — moderate pool of light around player
4116| - Cubic falloff instead of quadratic: `alpha = pow(clamp(1.0 - dist, 0.0, 1.0), 3.0)` — steep center dropoff with a long, gentle tail that blends into the ambient darkness
4117| - `blend_mode = BLEND_MODE_ADD` (keep) — adds to ambient rather than replacing
4118| - `energy` driven by `get_moonlight_energy()` (keep)
4119| 
4120| #### 6. CanvasModulate Update
4121| 
4122| Current: `Color(ambient.r * b, ambient.g * b, ambient.b * b)` — multiplies ambient tint by brightness.
4123| 
4124| This is correct. The ambient color from the updated `get_ambient_color()` (with smoothstep + extended boundaries) will automatically produce the golden hour warmth, deep blue nights, and warm peach sunrises.

4211| # Terrain Object System Design
4212| 
4213| **Date:** 2026-05-28
4214| **Status:** Approved
4215| **Scope:** Object taxonomy, interaction framework, biome placement, animation system, generation pipeline
4216| 
4217| ## Overview
4218| 
4219| Every biome in FreedomMMO is composed of atomic, layered, animated objects — not flat textures. This spec defines the three-axis relational model that governs what objects exist, what can happen to them, where they appear, and how they're generated at scale.
4220| 
4221| The three axes:
4222| 1. **Object Catalog** — what exists (animate/inanimate, lifecycle phases, durability stages)
4223| 2. **Interaction Schema** — what can happen to it (trigger conditions, effects, animation specs)
4224| 3. **Biome Affinity Matrix** — where it appears (density, clustering, elevation/moisture rules, transitions)
4225| 
4226| These are supported by:
4227| - **Placement Engine** — deterministic seeded placement + sparse time-decaying deltas
4228| - **Animation Framework** — priority-based resolution, compositing, blend modes
4229| - **Generation Pipeline** — systematic PixelLab orchestration across the full matrix
4230| - **File Organization** — directory structure with extension point documentation for future agents
4231| 
4232| Target scale: ~200+ base object types, ~30 interaction types, ~6 lifecycle phases average = **4,000-6,000 unique animation sets**. Thousands of individual assets, each with dozens to hundreds of animations.
4233| 
4234| ---

4329| ### 1.4 Object Production Graph
4330| 
4331| Every transformation produces objects that themselves exist in the catalog:
4332| 
4333| ```
4334| oak_tree (mature) --[chop]--> oak_stump + oak_log + branch ×3 + leaf_pile
4335| oak_log --[chop]--> plank ×4 + wood_chip
4336| oak_tree (mature) --[burn]--> charred_trunk + ash_pile
4337| oak_tree (mature) --[lifecycle]--> dying --> dead --> fallen_log + mushroom_cluster
4338| 
4339| granite_boulder --[strike ×4]--> cracked --> fractured --> shattered
4340| shattered --[break_products]--> rock_chunk ×3 + pebble ×8 + stone_dust
4341| rock_chunk --[strike]--> pebble ×4 + stone_dust
4342| ```
4343| 
4344| Nothing disappears — it becomes something else. The catalog is a closed graph of transformations.

4400| ### 1.6 Individuality & Future Identity System
4401| 
4402| **Current scope:** Visual variance only. Each ObjectInstance gets an `instance_seed` that drives:
4403| - Scale variance (0.85–1.15×)
4404| - Lean angle (-5° to +5°)
4405| - Color/hue shift (-10° to +10°)
4406| - Branching seed (for trees — fractal variation)
4407| - Leaf/foliage density variation
4408| 
4409| **Extension point for future agents:** The `variance` block on animate objects is the hook for identity. When the identity system is built:
4410| - Add `identity_id` to ObjectInstance linking to EntitySystem
4411| - Extend variance with `growth_history` (this tree grew near water = taller), `damage_scars` (struck by lightning = scar texture), `relationship_to_neighbors` (crowded forest = thinner canopy)
4412| - ObjectInstance becomes a persistent entity tracked across sessions
4413| - See `data/terrain_objects/schema/EXTENSION_POINTS.md`

4419| ### 2.1 Interaction Categories
4420| 
4421| ```
4422| traversal/          — entity movement through/past the object
4423|   walk_through        entity enters tile, requires: non_blocking
4424|   run_through         entity sprinting, requires: non_blocking
4425|   swim_past           entity in water, adjacent to object
4426|   fly_over            flying entity above
4427|   land_on             entity descends onto tile
4428|   push_aside          entity walk + object is pushable
4429| 
4430| player_action/      — deliberate actions by entities (players and NPCs)
4431|   chop                tool=axe, target: vegetation
4432|   mine                tool=pickaxe, target: mineral
4433|   dig                 tool=shovel, target: ground_cover
4434|   pick                hand, target: size=[1,1] + pickable
4435|   burn_ignite         tool=torch OR spell=fire, target: flammable
4436|   freeze_cast         spell=frost
4437|   plant               hand+seed, target: empty_soil
4438|   water               tool=bucket, target: vegetation
4439|   climb               hand, target: climbable + size >= [1,2]
4440| 
4441| environmental/      — world forces acting on objects
4442|   wind                weather.wind_speed > threshold, intensity scales with speed
4443|   rain                weather.precipitation > 0
4444|   lightning           weather.lightning_strike at tile
4445|   flood               water_level rises into tile
4446|   drought             soil_moisture < threshold over time
4447|   fire_spread         adjacent tile burning + flammable
4448|   erosion             continuous water/wind exposure over time
4449| 
4450| biome_blending/     — transitions between biome boundaries
4451|   edge_fade           tile is biome boundary, contextual sprites
4452|   submersion          water encroaching on land tile
4453|   overgrowth          vegetation biome advancing into barren
4454| 
4455| ambient/            — always-on default animations
4456|   idle                always, default loop
4457|   idle_variant        random interval, occasional variation
4458|   day_shift           time_of_day crosses dawn threshold
4459|   night_shift         time_of_day crosses dusk threshold
4460|   seasonal_change     season transition (spring/summer/autumn/winter)
4461| 
4462| state_reactive/     — animations triggered by state changes

4509| ### 2.3 The Multiplication Constraint
4510| 
4511| The interaction schema constrains the combinatorial space. Not every object supports every interaction — a rock doesn't need `seasonal_change`, grass doesn't need `mine`. Each object's lifecycle phases explicitly list applicable interactions, making the generation matrix tractable.
4512| 
4513| Estimated valid combinations: ~4,000-6,000 unique animation sets across all objects × phases × interactions.
