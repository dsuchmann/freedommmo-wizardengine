2267| # Visual Quality Spec — Reference-Grade Pixel Art Rendering
2268| 
2269| ## Goal
2270| Match the visual quality of Sea of Stars, CrossCode, and modern indie pixel art RPGs. Every screen should look like a painting — no empty spaces, no visible tile grids, dense detailed environments.
2271| 
2272| ## Reference Analysis
2273| The reference games achieve their look through:
2274| 1. **32-64px tiles** at 1:1 or slight zoom — each tile has visible internal texture
2275| 2. **Dense object coverage** — forests have trees nearly touching, villages have objects everywhere
2276| 3. **Multi-layer rendering** — ground, shadows, objects, canopy overlay, lighting
2277| 4. **Seamless terrain** — no visible tile boundaries between adjacent tiles
2278| 5. **Rich decorative detail** — barrels, fences, flowers, signs, lamps fill every gap

2344| # Asset Pipeline Spec — Layered Cel-Animation Terrain System
2345| 
2346| **Date:** 2026-05-26
2347| **Status:** Draft
2348| **Scope:** How terrain assets are generated, organized, quality-gated, and cataloged.
2349| 
2350| ## Core Principle: Cel-Animation Layering
2351| 
2352| Every visible tile is composed of 5 semi-transparent layers stacked together, like animation cels. Each layer is independently swappable based on tile state (pristine, disturbed, burning, etc.). Layers composite at runtime via z-ordered Sprite2D nodes or shader blending.
2353| 
2354| Nothing is a single opaque image. Everything decomposes into atomic layers.
2355| 
2356| ## The 5 Sub-Layers (per biome)
2357| 
2358| | Sub-Layer | Z | Content | Opacity | Examples |
2359| |-----------|---|---------|---------|----------|
2360| | **L1: Base Ground** | 0 | Opaque ground surface — the foundational terrain | 100% opaque | Dirt, sand, stone, snow, mud, lava rock, crystal |
2361| | **L2: Ground Detail** | 1 | Surface texture patterns overlaid on base | Semi-transparent | Cracks, moss patches, puddles, root networks, frost patterns |
2362| | **L3: Vegetation** | 2 | Growing things attached to the ground | Semi-transparent | Grass blades, flowers, mushrooms, lichen, coral, crystals |
2363| | **L4: Scatter Objects** | 3 | Small loose items on the surface | Semi-transparent | Pebbles, shells, bones, fallen leaves, embers, ice shards |
2364| | **L5: Atmospheric** | 4 | Environmental particle effects near ground | Semi-transparent | Dust motes, mist wisps, pollen, volcanic ash, magical sparkles |
2365| 
2366| Not every biome uses all 5 layers. Ocean might only use L1 + L5 (water + foam). Desert might use L1 + L2 + L4 (sand + ripples + rocks). But the architecture supports all 5 everywhere.
2367| 
2368| ## Tile States
2369| 
2370| Each tile position tracks a state. Each state maps to different frames per layer:
2371| 
2372| | State | Trigger | Duration | Visual Effect |
2373| |-------|---------|----------|---------------|
2374| | **pristine** | Default | Permanent until changed | Normal appearance |
2375| | **disturbed** | Player walks through | 3-5 seconds | L3 vegetation sways/parts, L4 scatters shift |
2376| | **trampled** | Repeated foot traffic | 30-60 seconds | L3 flattened, L2 shows wear path |
2377| | **dug** | Dig action | Persistent | L1 shows hole, L2-L5 removed |
2378| | **burning** | Fire event | 5-10 seconds | L3-L5 replaced with flame frames, L1 darkens |
2379| | **burned** | After burning completes | Persistent until regrow | L1 scorched, L2 ash, L3-L5 gone |
2380| | **wet** | Rain/splash | 15-30 seconds | L2 shows puddles/sheen, L5 shows droplets |
2381| | **frozen** | Cold/magic | Persistent until thaw | L2 frost overlay, L3 ice-coated, L5 ice crystals |
2382| | **recovering** | After disturbed/trampled | Transition | Gradual return to pristine frames |
2383| 
2384| **Phase 1 generates pristine state only.** Architecture supports all states from day one.
2385| 
2386| ## Wang Tileset Format
2387| 
2388| Each layer is a standard 16-tile Wang tileset (corner-based autotiling). This means:
2389| - 16 tiles per layer per state per biome
2390| - Each tile is 32x32 pixels
2391| - L1 is FORMAT_RGBA8 fully opaque
2392| - L2-L5 are FORMAT_RGBA8 with transparency (alpha channel matters)
2393| 
2394| ## PixelLab Generation Rules
2395| 
2396| ### Self-Tilesets (base terrain)
2397| - Use `create_topdown_tileset` with `tile_size: {width: 32, height: 32}`
2398| - L1: `lower_description` = base terrain, `upper_description` = same terrain variant (self-transition)
2399| - L2-L5: Generate as separate tilesets with transparent backgrounds
2400|   - Use very specific prompts: "scattered small pebbles and stones on transparent background, pixel art, top-down view"
2401|   - Set `detail: "highly detailed"` and `shading: "detailed shading"`
2402| 
2403| ### Transition Tilesets
2404| - Transitions only apply to L1 (base ground)
2405| - Use `lower_base_tile_id` / `upper_base_tile_id` to chain with existing base tiles
2406| - L2-L5 transitions are handled by alpha blending at runtime (no dedicated transition tilesets needed)
2407| 
2408| ### Quality Gates
2409| Before accepting a generated tileset:
2410| 1. **Visual coherence**: Does it look like the biome it represents?
2411| 2. **Tileability**: Do tiles connect seamlessly at Wang boundaries?
2412| 3. **Scale consistency**: Are details appropriately sized for 32x32?
2413| 4. **Transparency correctness**: For L2-L5, is the background truly transparent (not colored)?
2414| 5. **Distinctiveness**: Does this biome look different from every other biome?
2415| 
2416| If a tileset fails any gate, regenerate. Don't compromise.

2514|

2796| # Dynamic Lighting & Shading System
2797| 
2798| > Established 2026-05-26. Authoritative spec for Layers -1 and 7: terrain shading and dynamic world lighting.
2799| 
2800| ## Problem
2801| 
2802| The terrain is flat-looking — elevation data exists but isn't visually communicated. There's no day/night cycle, no shadow direction, no atmosphere. The world feels static.
2803| 
2804| ## Solution
2805| 
2806| A unified lighting system with a moving sun/moon, terrain normal maps for dynamic hillshading, global ambient tint for atmosphere, and infrastructure for building occlusion and point lights.
2807| 
2808| ## Architecture
2809| 
2810| ```
2811| DayNightCycle (time source)
2812|   → drives DirectionalLight2D (sun/moon angle, color, intensity, height)
2813|   → drives CanvasModulate (global ambient tint)
2814|   → drives HUD (time display in dev mode)
2815| 
2816| NativeChunkCompiler (C++)
2817|   → generates terrain Image (existing)
2818|   → generates normal map Image (new — from elevation data)
2819|   → bakes static ambient occlusion into terrain image (new)
2820| 
2821| ChunkStreamer
2822|   → assigns terrain texture + normal map to each chunk Sprite2D
2823| 
2824| Future:
2825|   Building tiles → LightOccluder2D (walls block light, windows pass)
2826|   Object system → PointLight2D (torches, campfires, lanterns)
2827| ```
2828| 
2829| ## Component 1: Sun/Moon Directional Light
2830| 
2831| A single `DirectionalLight2D` node represents the dominant sky light source.
2832| 
2833| ### Sun Arc (Dawn to Dusk)
2834| 
2835| The sun moves west to east across the sky:
2836| 
2837| | Game Hour | Period | Angle (degrees) | Height | Color | Energy |
2838| |-----------|--------|-----------------|--------|-------|--------|
2839| | 5:00 | Dawn start | 270 (west) | 0.2 | Warm orange (1.0, 0.6, 0.3) | 0.3 |
2840| | 7:00 | Morning | 240 | 0.5 | Soft yellow (1.0, 0.9, 0.7) | 0.8 |
2841| | 12:00 | Noon | 180 (overhead-south) | 1.0 | White (1.0, 1.0, 0.95) | 1.0 |
2842| | 17:00 | Golden hour | 120 | 0.5 | Deep amber (1.0, 0.7, 0.3) | 0.8 |
2843| | 18:00 | Dusk start | 100 | 0.3 | Red-orange (0.9, 0.4, 0.2) | 0.4 |
2844| | 20:00 | Dusk end | 90 (east) | 0.1 | Fading (0.4, 0.2, 0.15) | 0.1 |
2845| 
2846| ### Moon Arc (Night)
2847| 
2848| | Game Hour | Angle | Height | Color | Energy |
2849| |-----------|-------|--------|-------|--------|
2850| | 20:00 | 270 (west) | 0.1 | Cool blue (0.2, 0.25, 0.45) | 0.15 |
2851| | 0:00 | 180 (overhead) | 0.4 | Silver-blue (0.25, 0.3, 0.5) | 0.2 |
2852| | 5:00 | 90 (east) | 0.1 | Fading blue (0.15, 0.2, 0.35) | 0.1 |
2853| 
2854| All values smoothly interpolated using the existing `DayNightCycle` hour as the driver. No hard transitions.
2855| 
2856| ### Height Property
2857| 
2858| The `height` property on DirectionalLight2D controls how "steep" the light hits the surface:
2859| - Low height (0.1-0.3) = long dramatic shadows at dawn/dusk
2860| - High height (0.8-1.0) = short/no shadows at noon
2861| - This interacts with the terrain normal maps to create realistic hillshading
2862| 
2863| ## Component 2: Terrain Normal Maps
2864| 
2865| For each chunk, the C++ `build_chunk_image` generates a second Image — the normal map.
2866| 
2867| ### Normal Map Generation (in NativeChunkCompiler)
2868| 
2869| For each tile at position (x, y):
2870| 1. Sample elevation at (x-1, y), (x+1, y), (x, y-1), (x, y+1) — we already compute this for the slope array
2871| 2. Compute surface normal: `nx = (left - right) * scale`, `ny = (up - down) * scale`, `nz = 1.0`
2872| 3. Normalize the vector
2873| 4. Encode to RGB: `R = nx * 0.5 + 0.5`, `G = ny * 0.5 + 0.5`, `B = nz * 0.5 + 0.5`
2874| 5. Scale = tuning parameter controlling how dramatic the shading is (start with 4.0)
2875| 
2876| Output: 2048x2048 RGBA8 Image (same size as terrain image), where each tile's 32x32 pixel block has the same normal value (flat within each tile — variation comes from tile-to-tile differences).
2877| 
2878| ### Sprite2D Material Setup
2879| 
2880| Each chunk Sprite2D gets a `CanvasItemMaterial` with:
2881| - `texture` = terrain image (existing)
2882| - `normal_map` = normal map image (new)
2883| - `light_mode` = default (responds to Light2D nodes)
2884| 
2885| This is all Godot needs to shade the terrain dynamically under the DirectionalLight2D.
2886| 
2887| ### Static Ambient Occlusion
2888| 
2889| Baked into the terrain image (not the normal map):
2890| - For each tile, compute an AO factor from the surrounding elevation
2891| - Valleys (elevation lower than average of 8 neighbors) get darkened by 5-15%
2892| - Ridges (elevation higher than average) get lightened by 3-8%
2893| - This provides base depth even without the dynamic light
2894| 
2895| ## Component 3: Global Ambient Tint
2896| 
2897| A `CanvasModulate` node applies a color tint to the entire scene.
2898| 
2899| | Period | Color | Purpose |
2900| |--------|-------|---------|
2901| | Night (20:00-5:00) | (0.15, 0.15, 0.3) | Dark blue atmosphere |
2902| | Dawn (5:00-7:00) | Lerp → (1.0, 0.9, 0.85) | Warm morning transition |
2903| | Day (7:00-17:00) | (1.0, 1.0, 0.95) | Neutral, slightly warm |
2904| | Golden hour (17:00-18:00) | Lerp → (1.0, 0.85, 0.6) | Amber evening |
2905| | Dusk (18:00-20:00) | Lerp → (0.15, 0.15, 0.3) | Fade to night |
2906| 
2907| These values come from the existing `DayNightCycle.get_ambient_color()` method, which already implements similar logic. We'll refine the exact values to work well with the DirectionalLight2D.
2908| 
2909| ## Component 4: Building Light Occlusion (Future-Ready)
2910| 
2911| Not implemented in this phase, but the system design accommodates it:
2912| 
2913| - Wall tiles → `LightOccluder2D` polygons (block directional + point lights)
2914| - Window tiles → no occluder (light passes through)
2915| - Door tiles → conditional occluder (closed = block, open = pass)
2916| - Interior tiles without light sources are naturally dark
2917| - The building layer (Layer 3) will add occluders when it's built
2918| 
2919| No code needed now. The DirectionalLight2D and normal map system work correctly whether occluders exist or not.
2920| 
2921| ## Component 5: Point Light API (Future-Ready)
2922| 
2923| Not implemented in this phase. When the object/building systems are built:
2924| 
2925| - Torches, campfires, hearths, lanterns = `PointLight2D` nodes
2926| - API: `create_light(world_pos: Vector2, color: Color, radius: float, energy: float, flicker: bool) -> Light2D`
2927| - Flicker = small random energy variation per frame
2928| - Managed by a LightManager that pools and recycles Light2D nodes (don't create/destroy per chunk)
2929| 
2930| No code needed now.
