# F5 Wiring + Field Registry Design

**Date:** 2026-06-12
**Status:** Approved by user (live in-game calibration of all aspects of every field)

## Goal

Wire F5 (medium objects — boulders, ruins, fallen logs; 96px sprites in
`assets/pixelab/landscape_v2/micro/medium_objects/<biome>/<object>/`) into the
game so objects place and render live, and make the unified field tuner
data-driven so F5 — and every future field — appears in the panel with all
aspects tunable: size, density, animation toggles, and state mix.

## Context

- F4 (medium flora, 64px) is the template: generated catalog
  (`scripts/gen-mf-catalog.mjs` → `src/world/mf-catalog.js`),
  `f4Placements()` in `src/world/decoration-claims.js` (claims + tuning
  hooks), main-thread y-sorted draw in `src/render/field2-animator.js`.
- F5 base variants exist on disk for all 16 biomes (3 objects each, `mo__`
  prefix). States are generating on PixelLab now (cracked, destroyed,
  mossy_overgrown, burned, frozen, enchanted); anims not started.
  Taxonomy already declared in `src/world/asset-state-taxonomy.js:52`.
- The tuner (`src/dev/field-tuner.js`) hand-writes its field list
  (`FIELDS = ['f2','f3','f4']`) and per-field object discovery.

## Decisions (user-confirmed)

1. **States from day one.** Placement rolls a state immediately; a missing
   state PNG falls back to the base variant sprite until the download lands.
   The roll is real, the art streams in — honest absence, never fake.
2. **Bigger claims only.** F5 registers claim footprints ~2× F4's so
   F2/F3/F4 don't spawn inside object bases. No player collision yet —
   that arrives with the object-permanence kernel work.
3. **Field registry module.** The tuner iterates a registry; future fields
   (F6/F7) are one registry entry, zero tuner edits.
4. **All aspects tunable live**, including state-mix weights.

## Architecture

### 1. Catalog: `src/world/mo-catalog.js` (generated)

Extend `scripts/gen-mf-catalog.mjs` to scan `medium_objects/` alongside
`medium_flora/` and emit `MO_CATALOG` with the same shape as `MF_CATALOG`:
per biome → object → `{ variants, states: [names], anims: [categories] }`.
Regenerated by hand (or by the asset runners' caller) as new art lands.

### 2. Placement: `f5Placements(wx, wy, tileInfo)` in `decoration-claims.js`

Mirrors `f4Placements` with fresh salts (no collisions with existing salt
ranges — pick a new 9800+ block and document it next to the others):

- **Density:** per-biome tile chance, rarer than F4 (defaults ~1–3%,
  forest/mystic at the high end, desert/arctic low), ×
  `tuneBiomeDensity('f5', biome)`; object cull via
  `tuneObjDensity('f5', biome, name)`.
- **Size:** base scale 1.0 at 96px (≈3 tiles), × per-biome scale table ×
  `tuneSize('f5', biome, name, variant, wx, wy, salt)`.
- **State roll:** defaults — base 60%, weathered (cracked / mossy_overgrown /
  burned / frozen, biome-appropriate subset) 32%, destroyed 6%, enchanted 2%.
  Weights are overridable via the tuning tree (see §4). Rolled
  deterministically per placement.
- **Claims:** footprint ellipse ~2× F4's relative size; registered in the
  same 8×8 claim-mask raster so F2 blades / F3 scatter / F4 flora avoid it.
  One placement per tile; a tile claimed by F5 is skipped by F4 (existing
  claim-mask mechanics, no new exclusion code).
- **Mutual order:** F5 claims first (larger object claims first, per locked
  atlas decision #7), then F4, then smaller fields fill remaining space.

### 3. Rendering: F5 joins the y-sorted pool in `field2-animator.js`

- Descriptor built per placement: `staticUrl` =
  `mo__<biome>__<name>__v<pad3>.png`; if a state was rolled and
  `MO_CATALOG` says its PNG exists, swap to the state URL — **otherwise
  keep the base URL** (fallback rule).
- 96px draw size; `sortYOff` tuned for tall sprites so the player y-sorts
  correctly behind/in front of object bases.
- No animation playback yet (no frames on disk). The
  `tuneAnimEnabled('f5', …)` gate is checked so the toggle is honest when
  anims later exist.
- Frame cache / denoise pipeline reused as-is (keyed by URL).

### 4. Tuning tree: new `states` node

The resolver (`src/world/field-tuning.js`) gains one lookup:

```js
// f5.biomes.<biome>.objects.<obj>.states = { base: 60, cracked: 10, ... }
// Missing node = field defaults. Weights are relative (normalized at roll).
tuneStateWeights(field, biome, obj, defaults) -> { name: weight, ... }
```

Resolution: object node → biome node → field master → built-in defaults
(same cascade as size/density). `f5Placements` rolls its state through this.
F2/F4 lifecycle mixes migrate onto the same mechanism (their current
hardcoded 15/55/20/10 splits become the field defaults) so every field's
state mix is tunable from the panel.

### 5. Field registry: `src/dev/field-registry.js`

Small module exporting an ordered list of field descriptors:

```js
{
  id: 'f5',
  label: 'F5 medium objects',
  objectsFor(biome) -> [names],          // from MO_CATALOG
  variantsFor(biome, obj) -> count|list, // from MO_CATALOG
  animCategories: ['wind_sway'],          // gates rendered as toggles
  stateNames(biome, obj) -> [names],      // states rendered as weight sliders
  applyKind: 'live' | 'repaint-bitmaps',  // f3 = repaint-bitmaps, rest live
}
```

`field-tuner.js` builds tabs by iterating the registry, renders size/density
sliders (master / biome / object / variant — unchanged), anim toggles from
`animCategories`, and state-weight sliders from `stateNames`. `apply()`
consults `applyKind` instead of hardcoding `field === 'f3'` (the f3-pending
debounce coalescing keys off `applyKind === 'repaint-bitmaps'`). Copy-JSON
export and localStorage persistence unchanged.

Adding F6/F7 later = write one registry entry pointing at their catalog.

### 6. Cache invalidation

F5 placements are cached in decoration-claims like F4's; `apply()` already
calls `clearClaimCaches()` + `clearF2TileDescriptors()`, which covers F5
(same caches). State-weight edits invalidate the same way. No worker
involvement (F5 never bakes into chunk bitmaps).

## Error handling

- Missing state PNG → base variant sprite (by catalog check, not 404).
- Missing base PNG (shouldn't happen) → placement skipped, console warn once.
- Malformed tuning tree nodes → resolver returns defaults (existing rule).

## Testing

1. **Unit (node:test):** `f5Placements` determinism (same inputs → same
   output), density-0 → empty, size multiplier flows to scale, state roll
   respects `tuneStateWeights` overrides (e.g. enchanted:1 / rest:0 → always
   enchanted), claim mask larger than F4's, F4 skips F5-claimed tiles.
2. **Resolver unit:** `tuneStateWeights` cascade (object > biome > master >
   defaults), normalization, missing-node behavior.
3. **Integration probe:** extend `scripts/probe-field-tuning.mjs` — f5 tab
   exists, slider edits resolve, registry-driven tabs match registry order.
4. **Visual:** F5 rides the proven F4 draw path; spot-check via tuner in
   game (user calibration session is the acceptance test). The F2 visual
   probe pattern is available if a regression gate is wanted later.

## Out of scope

- Player collision with F5 footprints (object-permanence kernel work).
- F5 anim playback (no frames generated yet; the gate is wired, playback
  lands when `anim/` dirs exist and the catalog regenerates).
- F6/F7 wiring (registry makes them cheap later).
